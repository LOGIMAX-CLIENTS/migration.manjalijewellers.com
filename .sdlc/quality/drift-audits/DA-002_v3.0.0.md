## The Core Problem

The validated `step-done` was never tested because no task was ever created. The agent did Steps 3-10 of bootstrap correctly (read SKILL.md, check handoff, run banner, run what-next). But when `what-next` said "IDLE", the agent didn't know to run `sdlc start` — it just started investigating.

---

## Root Cause

### 1. `what-next` tells the agent what to do WHEN a task exists, but not WHAT to do when IDLE

When `what-next` prints "IDLE — no active task. Run: python .sdlc/engine/cli.py start ...", the agent reads this as information, not as an instruction. It then falls back to GEMINI.md rules which say "read brain, search recipes, investigate."

### 2. SKILL.md says "follow the instruction from what-next" but what-next's IDLE instruction is weak

```
IDLE — no active task.
Run: python .sdlc/engine/cli.py start -t fix -m {module} -s "{description}"
```

This is a suggestion, not a command. The agent sees an IDLE pipeline and a user asking about a bug → it starts investigating the bug instead of starting a task.

### 3. GEMINI.md rules compete with SKILL.md rules

GEMINI.md says: "Read system brain, search recipes, read module brain BEFORE touching code."
SKILL.md says: "Run what-next before doing anything."

The agent follows BOTH — reads SKILL.md, runs what-next (sees IDLE), then follows GEMINI.md (brain reads, recipe search, investigation). GEMINI.md rules are processed FIRST in the context window and have higher perceived authority.

## What Needs to Change

### Fix 1: SKILL.md must explicitly say "Run sdlc start if IDLE"

Current SKILL.md says:
```
1. Run what-next before doing anything.
```

Should say:
```
1. Run banner → if IDLE, run: sdlc start -t {type} -m {module} -s "{summary}"
2. Run what-next → follow the instruction
```

### Fix 2: what-next IDLE output should be an imperative command, not a suggestion

Current:
```
IDLE — no active task.
Run: python .sdlc/engine/cli.py start -t fix -m {module} -s "{description}"
```

Should be:
```
⚠️ NO ACTIVE TASK — you MUST start one before doing anything.
Run NOW: python .sdlc/engine/cli.py start -t fix -m {module} -s "{description}"
Do NOT investigate, grep, or read code until a task is started.
```

### Fix 3: GEMINI.md Step Zero should defer to SDLC pipeline

When `.sdlc/SKILL.md` exists, GEMINI.md Step Zero (brain reads, recipe search) should NOT execute independently. They should only execute INSIDE the pipeline's `discover` step. Otherwise they compete.
