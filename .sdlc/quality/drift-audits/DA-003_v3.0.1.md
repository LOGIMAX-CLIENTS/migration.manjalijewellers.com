## Two Problems Found

### Problem 1: CLI BUG — Track field empty string 🔴

When `sdlc start` creates a new task, it sets `"track": ""` instead of `"track": "STANDARD"`. The `what-next` command then fails with:

```
⚠️  No steps defined for track:
Check .sdlc/steps.json
```

The agent had to manually edit `pipeline.json` (violating rule 6) to fix this. **This is a CLI code bug, not an agent behavior issue.**

**Fix**: In `cmd_start()`, set `"track": "STANDARD"` as default instead of empty string.

### Problem 2: Agent parallelizes work alongside background discover 🟡

When `discover` ran as a background task, the agent said:
> "While discover runs, let me start searching for recipes and reading brain docs manually — the key investigation work."

This defeats the purpose of `discover` — it's supposed to do the brain reads, recipe search, etc. The agent duplicated that work alongside it.

**Root cause**: Step 1 instruction says "Wait for discovery.md to be generated" — but the agent interprets "wait" as "do something useful in parallel."

**Fix**: Step 1 instruction should explicitly say "Do NOT start any investigation while discover runs."
