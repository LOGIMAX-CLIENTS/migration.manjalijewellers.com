# /auto-fix — Automated Bug Fix Propagation

## Prerequisites

1. **Fingerprint scan completed** — run with `--bug-scan` to identify which patterns exist in a the client
2. **Recipe exists** for the bug pattern in the central `LOGIMAX-CLIENTS/bug-recipes` repo
3. **Client repo mapped** in `AI_Bug_Fix_System/fingerprint/client_registry.json`

## Workflow Steps

### Step 1: Identify Target Bug + Client

The user will specify:
- A **bug pattern ID** (e.g., `PAT-TXN-002`) or **recipe name** (e.g., `recipe_trans_complete`)
- A **client name** (e.g., `srjewellery`) or `--all` for batch

If the user doesn't specify, run the fingerprint scan first:
```powershell
php fingerprint.php --source="d:\XAMPP\htdocs\retail_v5" --client="<path>" --client-name="<name>" --bug-scan --fix-tracker
```

### Step 2: Load Recipe

Read the recipe from the **central repo**:

#### Mode 1 — GitHub MCP (preferred):
```
mcp_github-mcp-server_get_file_contents(
    owner: "LOGIMAX-CLIENTS",
    repo: "bug-recipes",
    path: "recipes/<recipe_name>.md"
)
```

#### Mode 2 — Git CLI fallback:
```powershell
$bugRecipesPath = Join-Path (Split-Path $env:PROJECT_ROOT -Parent) "bug-recipes"
if (Test-Path $bugRecipesPath) {
    cd $bugRecipesPath; git pull origin main
    Get-Content "recipes/<recipe_name>.md"
}
```

If both MCP and Git CLI fail, **STOP and alert the developer** — recipe is required before applying a fix.

The recipe MUST contain:
- `## Detection` — grep/search command to find instances
- `## Fix` — before/after code blocks with:
  ```
  ### Before
  (exact code to find)
  ### After
  (exact replacement code)
  ```
- `## Files` — which files to check (e.g., `admin/application/controllers/admin_ret_billing.php`)
- `## Verification` — what to check after fix

### Step 3: Read Client File from GitHub

Look up the client in `client_registry.json` to get:
- `github_org` (usually `LOGIMAX-CLIENTS`)
- `github_repo` (e.g., `erp.srjewellery.in`)
- `default_branch` (e.g., `STAGING`)

Use MCP tool:
```
mcp_github-mcp-server_get_file_contents(
    owner: "LOGIMAX-CLIENTS",
    repo: "<repo_name>",
    path: "<file_path from recipe>",
    ref: "<default_branch>"
)
```

### Step 4: Apply Fix

1. Read file content from GitHub response
2. Find the **Before** code block from the recipe
3. Replace with the **After** code block
4. Verify the replacement was made (count before vs after)

> **CRITICAL**: If the Before pattern is NOT found in client code, STOP.
> The client may have a customized version. Log it and move to next client.

### Step 5: Create Branch + Push Fix

```
mcp_github-mcp-server_create_branch(
    owner: "LOGIMAX-CLIENTS",
    repo: "<repo_name>",
    branch: "fix/<pattern-id>-<short-description>",
    from_branch: "<default_branch>"
)

mcp_github-mcp-server_push_files(
    owner: "LOGIMAX-CLIENTS",
    repo: "<repo_name>",
    branch: "fix/<pattern-id>-<short-description>",
    files: [{ path: "<file_path>", content: "<fixed_content>" }],
    message: "fix(<module>): <pattern_id> — <description>"
)
```

### Step 6: Create Pull Request

```
mcp_github-mcp-server_create_pull_request(
    owner: "LOGIMAX-CLIENTS",
    repo: "<repo_name>",
    title: "fix(<module>): <pattern_id> — <description>",
    head: "fix/<pattern-id>-<short-description>",
    base: "<default_branch>",
    body: "<auto-generated from recipe>"
)
```

PR body template:
```markdown
## Auto-Fix: <Pattern ID>

**Bug**: <description from recipe>
**Severity**: <severity>
**Pattern**: <pattern_id>

### What Changed
<diff summary>

### Before
<code block>

### After
<code block>

### Verification
<steps from recipe>

---
*This PR was auto-generated by the AI Bug Remediation System.*
*Recipe: <recipe_name>.md*
```

### Step 7: Log Result

After creating the PR, record:
- Client name
- Pattern ID
- PR URL
- Status (success / pattern-not-found / error)
- Timestamp

### Batch Mode (--all clients)

When running for all clients:
1. Load `client_registry.json`
2. For each active client:
   a. Read the target file from GitHub
   b. Check if the Before pattern exists
   c. If yes: branch → push → PR
   d. If no: log "pattern not found" and continue
3. Output summary table at the end

## Important Rules

1. **NEVER push directly to STAGING or PRODUCTION** — always create a feature branch
2. **NEVER auto-merge** — PRs require human review
3. **If Before pattern not found**, do NOT attempt fuzzy matching — skip and log
4. **One PR per pattern per client** — don't bundle multiple fixes
5. **Always include the recipe name** in PR body for traceability
