What Is This System?

This is a new AI-assisted bug finding and fixing system layered on top of our existing codebase. It adds structured knowledge and repeatable workflows:

Documents describing how each module works — business rules, database tables, methods, and risks.

Step-by-step procedures to find, fix, test, and document bugs consistently.

The Complete Flow — Three Phases

🔷 Phase A: Build Knowledge (Before You Can Fix Bugs)

Run /build-module-brain (give: module name + file paths)

RoundCoverageWhat's Added
1~50%Module overview, method index
2~75%AJAX map, security, schema, settings
3~95%Business rules, views, model deep index
4+→ 100%Data flows, cross-module map, forensic template
⚠️ Keep running rounds until COVERAGE_TRACKER.md = 100%

🔷 Phase B: Build Cross-Module Knowledge (After 3+ Module Brains)

Run /build-system-brain → Creates 11 documents in _SYSTEM/

Re-run in "Incremental Add" mode (5 min) after each new module brain.

🔷 Phase C: Fix Bugs (Daily Work)

Step 1: /bug-intake-triage — Classify

Give: description + module → Get: Bug ID + severity + track

↓

Step 2: /fix-single-bug — Fix (give: Bug ID)

Diagnose → Locate → Assess → Fix → Syntax Check → Test → Approval → Close

↓

Step 3: /test-and-verify + /learn-and-improve

Test the fix → Update brain + patterns → Close GitHub issue

Important Rules — Before / During / After Code Changes

Before ANY Change

  • Read module brain
  • Check SHARED_TABLES.md
  • Check TAG_STATUS_MAP.md if tag_status involved
  • Check CLEANUP_GAPS.md if delete/cancel

During Changes

  • CI3 query builder — no raw SQL
  • No magic numbers
  • Business logic in models
  • parseFloat() + toFixed(2) for money
  • Server-side validation always

After Changes

  • Run /learn-and-improve
  • Update GitHub Issue
  • Update ACTIVE_BUGS.md

Common Mistakes to Avoid

❌ Never✅ Instead
Fix without reading the brainRead MODULE_BRAIN.md + _SYSTEM/
Write raw SQLUse CI3 query builder
Use magic numbers: where('status', 1)Use constants or comments
Copy-paste a functionExtend with a parameter
Skip /learn-and-improveAlways run it after fixes
Hardcode dates, UIDs, tax ratesUse ret_settings or config
Trust client form valuesRecalculate server-side
Put logic in controllersBusiness logic in models
